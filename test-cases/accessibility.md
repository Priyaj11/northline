## TC-ACC-004 Every form input has an associated label

**Requirement** REQ-ACC-002  
**Technique** Equivalence Partitioning  
**Layer** accessibility  
**Priority** High  
**Automation** automated (tests/accessibility/test_axe_scans.py::test_every_form_input_has_an_accessible_name)  
**Introduced in phase** 5

**Preconditions** The login, transfer and bill payment forms are reachable.

**Test data** every input on each form

**Steps**

1. For each form, check that every input has a programmatically associated label.

**Expected result** Every input has a label a screen reader can announce. A visible caption that is not associated in the markup does not count, because assistive technology reads the association, not the layout.

## TC-ACC-005 Complete a login using the keyboard alone

**Requirement** REQ-ACC-003  
**Technique** State Transition Testing  
**Layer** accessibility  
**Priority** High  
**Automation** manual  
**Introduced in phase** 5

**Preconditions** The login page is displayed and no pointing device is used.

**Test data** valid credentials, keyboard only

**Steps**

1. Reach the username field using the tab key alone.
2. Enter credentials and submit without using a mouse.
3. Observe the focus indicator at every step.

**Expected result** Login completes, tab order follows the visual order, and focus is visibly indicated throughout. Verified manually, because automated tooling cannot confirm that a focus indicator is actually perceivable.

## TC-ACC-007 Validation errors are announced, not only shown in colour

**Requirement** REQ-ACC-002  
**Technique** Negative Testing  
**Layer** accessibility  
**Priority** High  
**Automation** automated (tests/accessibility/test_axe_scans.py::test_a_validation_error_is_conveyed_by_more_than_colour)  
**Introduced in phase** 5

**Preconditions** The transfer form is displayed.

**Test data** an invalid amount that triggers a validation error

**Steps**

1. Submit an invalid amount.
2. Check that the error is associated with the field in the markup.
3. Check that the error is conveyed by more than colour alone.

**Expected result** The error is programmatically associated with the field and is conveyed by text as well as colour. Colour alone excludes colour-blind users and screen reader users at the same time.
