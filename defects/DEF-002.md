# DEF-002  The transfer endpoint declares JSON and returns plain text

Status:          Open
Severity:        Medium
Priority:        P3
Requirement:     Contract conformance, adjacent to REQ-TXN-003
Test cases:      Covered by tests/api/test_transfer_api.py and the Postman collection
Detected in:     Phase 3A, API shape discovery
Reproducibility: Consistent, every request

## Environment

  System Under Test: ParaBank, image parasoft/parabank
  Environment:       local
  Detected:          2026-08-29

## Summary

POST /services/bank/transfer returns HTTP 200 with the header
Content-Type: application/json, but the body is a plain English sentence rather
than JSON.

## Steps to reproduce

  1. POST /services/bank/transfer?fromAccountId=A&toAccountId=B&amount=0.01
     with the header Accept: application/json
  2. Inspect the Content-Type header and attempt to parse the body as JSON.

## Expected result

Either a JSON body matching the declared content type, or a content type of
text/plain matching the body that is actually sent.

## Actual result

    status:       200
    content type: application/json
    body:         Successfully transferred $0.01 from account #12345
                  to account #12456

Parsing the body as JSON raises an error.

## Evidence

Recorded in docs/sut-api-shapes.md, generated by scripts/discover_api_shapes.py
against the running instance. Every other endpoint tested returns a body that
matches its declared content type.

## Business impact

Any client that trusts the declared content type and calls a JSON parser
crashes on this endpoint. That includes generated client libraries, integration
partners, and API gateways that parse and re-serialise responses.

The severity is Medium rather than High because the transfer itself succeeds
and no money is affected. The impact is on integration reliability, not on
correctness of the ledger.

## Handling in the test suite

tests/api/test_transfer_api.py marks the contract test as a strict expected
failure referencing this defect. The Postman collection asserts the broken
behaviour deliberately, which is the equivalent mechanism: both go red the
moment the defect is fixed, forcing the tests to be updated rather than quietly
drifting out of date.
