# DEF-006  Credentials are carried in the URL path

Status:          Open
Severity:        High
Priority:        P2
Requirement:     REQ-SEC-003
Test cases:      TC-SEC-005
Detected in:     Phase 5B, security-adjacent suite
Reproducibility: Consistent, by design of the interface

## Environment

  System Under Test: ParaBank, image parasoft/parabank
  Environment:       local
  Detected:          2026-08-31
  First observed:    2026-08-29, Phase 1 endpoint discovery

## Summary

The login endpoint takes the username and password as URL path segments:

    GET /parabank/services/bank/login/{username}/{password}

Confirmed from the service's own description document rather than by sending
credentials anywhere new.

## Expected result

Credentials carried in a request body or an authorisation header.

## Actual result

Both appear in the path, so both appear in the URL.

## Business impact

A URL is recorded in places that are not treated as secret stores:

    web server access logs
    reverse proxy and load balancer logs
    browser history on the client machine
    the Referer header sent to any third party the page links to
    bookmarks and shared links

A password written into any of those is a password in plain text held by
systems whose operators never considered themselves custodians of credentials.
Log retention then keeps it for as long as the logs are kept.

Transport encryption does not help. HTTPS protects the request in transit and
the server still writes the full path to its access log at the other end.

## Scope of testing performed

The endpoint's declared shape was read from the service description document.
No additional credential was transmitted to demonstrate the finding, because
the declaration is sufficient evidence and sending one would put a real
password into the very logs this defect is about.
